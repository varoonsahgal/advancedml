Attention from first principles

A soft, differentiable dictionary lookup.

The art: three real causal attention heads on a sequence with a repeated segment, blended. Honey = a RoPE local head (the bright diagonal), coral = an attention-sink head (first column), teal = induction-style stripes where the repeated segment matches. Everything above the diagonal is masked: no peeking at the future.
Gradient Hive · Day 3 · Transformers4 / 38
The intuition

Every token asks; earlier tokens answer

  • query: what am I looking for?
  • key: what do I contain?
  • value: what I hand over if chosen

The output is an average of values, weighted by how well the query matches each key.

Walk the picture top to bottom. "it" emits a query. Each earlier token advertises a key. The dot products go through a softmax and become weights (here "bee" wins, 0.62). The output is the weighted mix of the values. Every step is differentiable, which is why it trains. Ask: what would a one-hot weight vector turn this into? (A hard dictionary lookup.)

Scaled dot-product attention · Vaswani et al. 2017

The whole idea in one line

$$\mathrm{Attention}(Q,K,V) = \mathrm{softmax}\!\Big(\frac{QK^\top}{\sqrt{d_k}} + M\Big)\,V$$
QKᵀEvery query against every key: a T×T score matrix.
√dkKeeps logits at unit variance so softmax still has gradients.
MCausal mask: 0 on the past, −∞ on the future.
VThe weights mix the values into the output.
This line is the entire attention operation. Multi-head attention runs it H times on smaller projections and concatenates the results. The mask M is what makes a decoder a language model: token i can only read tokens 0..i, so one forward pass trains on every next-token prediction at once.
Gradient Hive · Day 3 · Transformers6 / 38
Why divide by √dk?

Big dot products freeze the softmax

  • Unit-variance q, k ⇒ Var(q·k) = dk
  • Large logits ⇒ softmax goes one-hot
  • One-hot softmax ⇒ gradient ≈ 0
  • Divide by √dk: variance back to 1
Both curves are computed, not sketched. Unscaled, by d_k = 2048 the top key gets ~97% of the weight and the softmax Jacobian has nearly vanished, so nothing upstream learns. Scaled, both stay flat at every width. Lab 3.1, Part 2 reproduces the top panel. Ask: what happens if you divide by d_k instead of √d_k? (Logits shrink with width; attention becomes nearly uniform.)

Causal self-attention · PyTorch

Twelve lines you'll write before lunch

import math, torch

def causal_self_attention(x, W_qkv, W_o, n_heads):
    B, T, C = x.shape
    q, k, v = (x @ W_qkv).split(C, dim=-1)               # three projections, one matmul
    # (B, T, C) -> (B, heads, T, head_dim): heads become a batch dimension
    q, k, v = [t.view(B, T, n_heads, C // n_heads).transpose(1, 2) for t in (q, k, v)]
    att = (q @ k.transpose(-2, -1)) / math.sqrt(k.size(-1))  # (B, h, T, T) scores
    future = torch.triu(torch.ones(T, T, dtype=torch.bool), diagonal=1)
    att = att.masked_fill(future, float("-inf"))         # no peeking ahead
    y = att.softmax(dim=-1) @ v                          # weighted sum of values
    return y.transpose(1, 2).reshape(B, T, C) @ W_o      # concat heads, project

In production: F.scaled_dot_product_attention(q, k, v, is_causal=True) computes the same result with a FlashAttention kernel.

Point out: multi-head is just a reshape. One big QKV matmul, heads become a batch dimension, then concatenate and project. In Lab 3.1 they check their version against F.scaled_dot_product_attention to 1e-6. FlashAttention gives the exact same output; it just never materializes the T×T matrix in GPU main memory.

🍯 Key takeaway

Attention is a soft dictionary lookup: every token asks, every earlier token answers.

Queries ask, keys advertise, values deliver. Scale by √dk so it stays trainable; mask the future so training is honest.

The modern block, 2017 → 2026

One block, stacked dozens of times. The progress is in the details.

The art is RoPE: each ring is one of the 32 dimension pairs of a 64-dim head, and the dots are the rotation angle m·θᵢ for positions m = 0..399. Inner pairs spin fast and wrap around many times; outer pairs barely move. That's a bank of clocks running at different speeds.

The Llama-style decoder block

Pre-norm: read a normalized copy, add back

Original 2017 / GPT-2 → 2024–26 open LLMs: learned/sinusoidal positions → RoPE; post-norm LayerNorm → pre-norm RMSNorm (cheaper, stable for deep stacks); GELU 4× MLP → SwiGLU at ≈8/3× width (gated units score better per FLOP); one KV head per query head → GQA or latent attention (MLA); naive attention → FlashAttention; dense FFN → often mixture-of-experts. Pre-norm means the residual stream is never normalized in place, so gradients have a clean identity path through all N layers. Ask: in SwiGLU, which branch is the gate?

RoPE · Su et al. 2021

Positions as rotations

Rotate each 2-D pair of q and k by angle m·θi, with θi = 10000−2i/d.

$$\langle R_m q,\ R_n k\rangle = \langle q,\ R_{n-m}\,k\rangle$$
  • Scores depend only on the offset
  • Fast pairs: local order. Slow pairs: long range
Rotations preserve length and compose, so the score is a function of n − m only: the heat map is constant along every diagonal. No parameters are added. Context-extension tricks (Position Interpolation, NTK-aware scaling, YaRN) all work by changing the θᵢ frequencies. Lab 3.1 visualizes this exactly.

Grouped-query attention

Share K and V across query heads

  • Every query head stays
  • Each K/V head serves a group
  • KV cache shrinks by Hq / Hkv, often 4–8×
  • Quality close to full multi-head
Queries are cheap: they are computed fresh for the current token. Keys and values are what you cache for every past token, so sharing them shrinks the cache directly. Llama-style 8B models use 32 query heads and 8 KV heads (4×). MQA (1 KV head) saves the most but loses some quality. DeepSeek's latent attention (MLA) instead compresses K and V into a small shared latent.
Gradient Hive · Day 3 · Transformers14 / 38
🍯 Key takeaway

A 2026 block is the 2017 block with better defaults, not a new idea.

Pre-norm RMSNorm for depth, RoPE for relative position, SwiGLU per FLOP, GQA for a smaller cache. Learn these five and you can read almost any open model's source.

Gradient Hive · Day 3 · Transformers17 / 38
Prefill vs decode

Decode is memory-bound

  • Prefill: the whole prompt at once, big matmuls, compute-bound
  • Decode: one token per step; every weight is read from memory for ~2 FLOPs
  • Fix it by moving fewer bytes per token
This answers the morning puzzle. At batch 1, each weight (2 bytes in bf16) is loaded from HBM to do one multiply-add (2 FLOPs) for one token: arithmetic intensity ≈ 1, so you get 3.35 TB/s × 1 ≈ 3.35 TFLOP/s, about 0.3% of peak. Batching B requests shares each weight load across B tokens. The KV cache, quantization (int8/int4 weights halve or quarter the bytes) and speculative decoding are all attacks on the same wall. Real numbers are lower still: KV-cache reads add bytes too.
Gradient Hive · Day 3 · Transformers18 / 38
The KV cache

Trade memory for compute

Past keys and values never change, so store them instead of recomputing.

$$\text{bytes/token} = 2\,L\,H_{kv}\,d_h\,b$$
  • MHA at 128k context: 64 GiB for one sequence
  • GQA-8 cuts it 4×
2 for K and V, L layers, H_kv KV heads, d_h head dim, b bytes per element. For a 32-layer, 32-head, 128-dim model in fp16: 2·32·32·128·2 = 512 KiB per token. At 128k tokens that's 64 GiB, nearly a whole 80 GB GPU for one user. PagedAttention (vLLM, 2023) stores the cache in fixed-size pages like OS virtual memory: no fragmentation, shared prefixes, much bigger batches. FlashAttention tiles Q, K, V through on-chip SRAM with an online softmax, so the T×T matrix never touches main memory.
Gradient Hive · Day 3 · Transformers19 / 38
🍯 Key takeaway

Generation is memory-bound: count the bytes you move, not the FLOPs.

Batching, the KV cache, GQA, quantization, PagedAttention and FlashAttention are all ways of moving fewer bytes per useful token.

Speculative decoding

Draft fast, verify in one pass

  1. A small draft model proposes k tokens
  2. The big target scores all k in one forward pass
  3. Accept each with min(1, p/q); on a reject, resample from (p − q)+

Top: 200,000 simulated steps. Bottom: expected tokens per target pass, (1 − αk+1) / (1 − α).

Why this works: decode is memory-bound, so scoring k tokens in one pass costs about the same as scoring one. The accept/reject plus residual resampling is rejection sampling, and it recovers the target distribution exactly: the teal bars match the honey bars even though the draft (grey) is quite different. The draft only changes how many tokens you get per pass. The curve assumes each token is accepted independently with rate α. Lab 3.2 proves exactness empirically on a real model pair.

Decoding knobs

Same logits, different personalities

Dashed coral: renormalized after truncation. Min-p keeps p ≥ 0.1 × pmax, so it tightens when the model is sure.

Temperature divides the logits: below 1 sharpens, above 1 flattens. Top-k keeps a fixed number of tokens. Top-p keeps the smallest set whose total probability reaches p. Min-p drops anything under p × the top token's probability, so it adapts to confidence (Lab 3.2's figure shows this on real character distributions). Greedy decoding is not "most accurate": it loops and goes bland. Reasoning models are typically sampled at moderate temperature, which also makes majority voting possible (Day 5).
Gradient Hive · Day 3 · Transformers22 / 38
🍯 Key takeaway

Speculation changes the speed, never the distribution.

Accept with min(1, p/q), resample the residual, and you get exact samples from the big model. Samplers, by contrast, do change the output, often as much as fine-tuning does.

Beyond dense attention

Experts for capacity, state spaces for long context.

The art: the 16 decaying modes of an S4D-Lin state-space kernel, Re exp((−½ + iπn)t). Each mode is a damped oscillator; an SSM's memory is a weighted mix of these. Fixed decay rates are exactly what Mamba makes input-dependent.

Mixture-of-Experts

More parameters, same FLOPs

A router sends each token to its top-k of E expert MLPs.

  • Mixtral 8×7B: 2 of 8 experts
  • DeepSeek-V3: 671B total, ~37B active
  • Routers collapse without balancing
Total parameters grow with E; compute per token grows only with k. Left alone, routers collapse: popular experts get more tokens, train faster and become more popular. Fixes: the Switch Transformer auxiliary load-balancing loss, or DeepSeek-V3's auxiliary-loss-free per-expert bias (shown here). DeepSeek-V3 also uses many fine-grained experts plus always-on shared experts and MLA for a small KV cache. Lab 3.3 shows actual collapse in training. Ask: does a 671B MoE fit in the memory of a 37B dense model? (No: every expert must be stored.)

State-space models · Mamba

A fixed-size memory that chooses

$$h_t = \bar A_t h_{t-1} + \bar B_t x_t,\quad y_t = C_t h_t$$
  • O(T) compute, constant memory per token
  • Δ, B, C depend on the input
  • Linear in h ⇒ parallel scan
An SSM compresses the past into a fixed-size state, so generation needs constant memory instead of a growing KV cache. Earlier SSMs (S4) had fixed A, B, C: a decaying, input-independent kernel (left). Mamba makes Δ, B, C functions of the input, so the model decides when to write, keep or reset (right). Because the recurrence is linear in h, training can use a parallel associative scan (Lab 3.3). Attention still wins at exact recall and copying; SSMs win at very long sequences and constant-memory generation. In practice: hybrids, e.g. AI21's Jamba (2024) mixes Mamba layers, a few attention layers and MoE.
Gradient Hive · Day 3 · Transformers27 / 38
🍯 Key takeaway

MoE spends memory to save FLOPs. SSMs spend exact recall to save memory.

Neither is free, so frontier designs mix them: sparse experts for capacity, SSM layers for long context, a few full-attention layers for precise recall.

Q1

Why divide attention logits by √dk?

Dot products of d-dim unit-variance vectors have variance d. Scaling keeps the softmax out of its saturated, zero-gradient regime.
Q2

KV-cache size per token?

2 (K and V) × layers × KV heads × head dim × bytes per element.
Q3

What does grouped-query attention share?

Each K/V head is shared by a group of query heads, shrinking the KV cache by (query heads / KV heads).

Six equations worth memorizing

Attention

$$\mathrm{softmax}(QK^\top/\sqrt{d_k} + M)\,V$$

RoPE identity

$$\langle R_m q, R_n k\rangle = \langle q, R_{n-m} k\rangle$$

SwiGLU

$$W_2(\mathrm{SiLU}(W_1x)\odot W_3x)$$

KV cache

$$\text{bytes} = 2\,L\,H_{kv}\,d_h\,b\cdot T$$

Speculative accept

$$\min\big(1,\ p(x)/q(x)\big)$$

Selective SSM

$$h_t = \bar A_t h_{t-1} + \bar B_t x_t,\ y_t = C_t h_t$$

Day 3 · the honey jar · 1/2

🍯 What to remember

  1. Attention lets every token read from every earlier token, weighted by query–key match. The causal mask stops it from reading the future.
  2. Scale logits by 1/√dk so the softmax doesn't saturate and gradients keep flowing.
  3. RoPE rotates q and k by position, so scores depend only on relative offset.
  4. The KV cache trades memory for compute. At long context it dominates serving cost, which is why GQA and latent attention exist.
Gradient Hive · Day 3 · Transformers36 / 38
Day 3 · the honey jar · 2/2

🍯 What to remember

  1. Decoding settings (temperature, top-p, min-p) shape the output's character as much as fine-tuning does.
  2. Speculative decoding is exact: the target model's distribution is preserved; only the speed depends on the draft model.
  3. MoE separates parameters (memory) from FLOPs per token, and needs load balancing so experts don't collapse.
  4. SSMs give linear-time, constant-memory sequence modeling. Input-dependent selectivity is what makes them work, and hybrids with attention are common.
