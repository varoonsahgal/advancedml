The question of the day

Why does a 100-layer network train at all?

Gradient flow on a toy 2-D loss: every streamline follows −∇L downhill into a basin. A network does this in a billion dimensions, through 100 layers that each multiply the signal.
Hook. Ask the room: multiply 100 random numbers near 1. What do you get? Almost never something near 1: it explodes or vanishes. Yet we train 100-layer transformers routinely. Today is about the three or four inventions that make that possible, plus the machinery (autodiff, optimizers, schedules) that drives the descent. The figure is real: streamplot of −∇L for a sum of Gaussian wells.

01

Backprop is just bookkeeping

Record every operation on the way forward. Walk the graph backwards, applying the chain rule once per edge.

~25 minutes for this part. The key idea: reverse-mode autodiff gives the gradient of one scalar with respect to millions of parameters for about the cost of one extra forward pass.
Gradient Hive · Day 2 · Engine Room4 / 38
A computational graph

Values flow forward, gradients flow back

Adjoint rule: $\bar v_i = \sum_{j\,\in\,\text{children}(i)} \bar v_j\,\dfrac{\partial v_j}{\partial v_i}$. Each node only needs its local derivative.

Walk it slowly. Forward: x·w = −1.0, + b = −0.5, tanh = −0.46, L = 2.14. Backward starts with L̄ = 1. ∂L/∂y = 2(y−1) = −2.92. tanh' = 1 − y² = 0.79, so −2.30 flows into the + node, which copies it to both parents (b gets −2.30). The × node swaps: ∂L/∂w = −2.30·x = −4.60, ∂L/∂x = −2.30·w = 1.15. Ask: which node would need a += if x were used twice?
Gradient Hive · Day 2 · Engine Room5 / 38
Quick check

Why train with reverse-mode autodiff, not forward-mode?

It's more numerically stable
One scalar loss, millions of inputs: one backward pass gets every gradient
Forward mode can't handle nonlinearities
It uses less memory

B. Forward mode costs one pass per input; reverse mode costs one pass per output. With one loss, reverse wins by a factor of millions. The price is memory (D is backwards): it must store the forward activations.

Show of hands first. D is the trap: reverse mode uses MORE memory, which is why activation checkpointing exists. Forward mode is still useful for Jacobian-vector products (e.g. some second-order tricks).

Lab 2.1 preview · the whole engine

Autograd in 17 lines

class Value:
    def __init__(self, data, parents=()):
        self.data, self.grad = data, 0.0
        self._parents, self._backward = parents, lambda: None

    def __mul__(self, other):
        out = Value(self.data * other.data, (self, other))
        def _backward():          # local derivative × upstream grad
            self.grad  += other.data * out.grad
            other.grad += self.data  * out.grad
        out._backward = _backward
        return out

    def backward(self):
        order, seen = [], set()
        def topo(v):
            if v not in seen:
                seen.add(v); [topo(p) for p in v._parents]; order.append(v)
        topo(self); self.grad = 1.0
        for v in reversed(order): v._backward()
  • Record parents on every op
  • Sort topologically
  • Sweep in reverse, calling each local rule
  • += because a value used twice gets two contributions
This is micrograd's core (Karpathy). In the lab they'll add __add__, tanh, exp, pow, then a numpy tensor version with broadcasting, where the subtle part is summing gradients over broadcast dimensions. Ask: what breaks if we used = instead of +=? (A diamond-shaped graph: x used by two children.)
Gradient Hive · Day 2 · Engine Room7 / 38
🍯 Key takeaway

Backprop is the chain rule run backwards: every gradient for about one extra forward pass.

The bill arrives as memory: every activation from the forward pass waits around until the backward pass uses it.

Why deep nets train at all

Each layer multiplies the signal. Products of many numbers rarely stay near 1.

The art: activation histograms of a real 22-layer tanh MLP whose init is a bit too large (gain 1.6). Top: a narrow input; going down, the activations spread out and pile up at ±1, saturating tanh. Three inventions turned "deep" from impossible into routine: careful init, normalization, residual connections.
Gradient Hive · Day 2 · Engine Room9 / 38
Init, then highways

Keep the signal near 1

  • He init for ReLU: $\mathrm{Var}(w) = 2/\text{fan}_\text{in}$ keeps activations flat through 50 layers
  • Xavier ($2/(\text{fan}_\text{in}{+}\text{fan}_\text{out})$) suits tanh, but shrinks ReLU nets by $\sqrt 2$ per layer
  • Init only fixes the start. Residuals keep gradients alive all through training
Top panel: width-512 ReLU net, 50 layers. std=1 multiplies the scale by √(512/2) = 16 per layer. Xavier (here Var = 1/fan_in since the layers are square) loses a factor √2 per layer because ReLU zeroes half the inputs; He's factor 2 fixes exactly that. Bottom: PyTorch default init, plain tanh stack vs pre-norm residual blocks. The gradient reaching layer 1 is ~3×10⁻¹¹ of the last layer's in the plain net and about the same in the residual net.
Gradient Hive · Day 2 · Engine Room10 / 38
Normalization + residuals

The residual stream

$x_{l+1} = x_l + F\big(\mathrm{Norm}(x_l)\big)$

  • The identity path is a gradient highway to layer 1
  • Pre-norm: normalize each sublayer's input, so the stream stays an untouched sum
  • RMSNorm $= x/\sqrt{\overline{x^2}+\epsilon}\odot g$: LayerNorm minus the centering, and just as good
Every layer reads from and writes to a shared memory: the residual stream. ∂x_{l+1}/∂x_l = I + ∂F/∂x_l, so the identity term guarantees gradient flow. Post-norm (the original 2017 transformer) normalized after the add, putting a Norm on the highway itself; that needs careful warmup and gets unstable when very deep. Pre-norm makes warmup less critical. Day 3 builds exactly this block.
Gradient Hive · Day 2 · Engine Room11 / 38
🍯 Key takeaway

Deep nets train when no layer multiplies the signal far from 1.

Variance-preserving init sets the start, normalization holds the scale, and the residual stream gives every gradient a highway home.

03

Optimizers: SGD to Muon

The gradient says which way is downhill. The optimizer decides how far, and what to remember.

Welcome back from lunch. Seventy years in a few equations: Robbins–Monro SGD (1951) → momentum → Adam (2015) → AdamW (2019) → Muon (2024). The art: Muon's Newton–Schulz polynomial applied 0 to 7 times (bottom to top) on a log axis of singular values; each iteration lifts smaller singular values into the band around 1.
Gradient Hive · Day 2 · Engine Room14 / 38
Momentum → Adam → AdamW

Two running averages and a decoupled decay

$$\theta_t = \theta_{t-1} - \eta\Big(\frac{\hat m_t}{\sqrt{\hat v_t}+\epsilon} + \lambda\,\theta_{t-1}\Big)$$
$m_t$momentum: average of $g_t$ with $\beta_1 \approx 0.9$
$v_t$average of $g_t^2$: a per-coordinate step size
$\hat m, \hat v$bias-corrected for the zero start
$\lambda\theta$weight decay, outside the $\sqrt{\hat v}$
m_t = β1 m + (1−β1) g, v_t = β2 v + (1−β2) g², with β2 ≈ 0.95–0.999. Dividing by √v makes the step roughly scale-free per coordinate: about η in size regardless of gradient magnitude. The coral term is the whole point of AdamW (Loshchilov & Hutter 2019): decay applied directly to the weights, not added to the gradient.
Gradient Hive · Day 2 · Engine Room15 / 38
Why "decoupled" matters

Adam + L2 ≠ AdamW

Put $\lambda\theta$ in the loss and Adam divides it by $\sqrt{\hat v}$.

  • Busy weights (big $\sqrt{\hat v}$) barely decay
  • Quiet weights decay hard
  • AdamW: one rate, $e^{-\eta\lambda t}$, for all
Top: with L2 in the loss, the decay gradient λθ is rescaled by 1/√v. σ = 10 weights keep 80% of their size after 20k steps; σ = 0.01 weights are crushed in 2k steps. Bottom: AdamW, all four lines sit exactly on e^(−ηλt). This is why "weight_decay" in torch.optim.Adam and torch.optim.AdamW are different knobs. Ask: which weights in a transformer have the biggest gradients? (Often embeddings of frequent tokens, the final layers.)
Gradient Hive · Day 2 · Engine Room16 / 38
Muon · Jordan et al., 2024

Muon: orthogonalize

$M = U\Sigma V^\top \;\mapsto\; UV^\top$: all singular values → ~1

def newton_schulz5(G, steps=5, eps=1e-7):
    a, b, c = 3.4445, -4.7750, 2.0315   # tuned quintic
    X = G / (G.norm() + eps)            # σ's into [0, 1]
    tall = X.size(0) > X.size(1)
    if tall: X = X.T
    for _ in range(steps):
        A = X @ X.T
        X = a * X + (b * A + c * A @ A) @ X   # σ → ~1
    return X.T if tall else X

# hidden 2-D weights only (AdamW for the rest):
buf = mu * buf + grad
W -= lr * newton_schulz5(buf) * max(1, rows/cols)**0.5
Muon treats a weight matrix as a matrix, not a bag of numbers. Orthogonalizing the momentum sets all singular values to 1, so rare directions get as much push as dominant ones. Top: the quintic is tuned for speed, not exactness: after 5 steps outputs land in ~[0.7, 1.2], not exactly 1, and that turns out fine. Bottom: a real 256×256 momentum matrix from an MLP on digits. The top directions go to ~1; tiny ones (below ~10⁻³ of the norm) get boosted ~100× but don't reach 1 in five steps. Frontier: Moonshot's "Muon is Scalable for LLM Training" (2025) reported ~2× compute efficiency over AdamW, and a Muon variant trained Kimi K2.
Gradient Hive · Day 2 · Engine Room17 / 38
🍯 Key takeaway

Adam rescales each coordinate. Muon rescales each direction.

Modern stacks run both: AdamW (decay decoupled!) for embeddings, norms and heads; Muon for the big 2-D hidden matrices.

04

Learning-rate schedules

Hyperparameter #1 is the learning rate. #2 is how it changes over time.

The art is the argument of this section. Amber curves: warmup + cosine, one complete curve per training budget; you must pick the budget up front. White: WSD, a single flat trunk, with a short cooldown you can branch off at any checkpoint.
Gradient Hive · Day 2 · Engine Room19 / 38
Warmup · stable · decay

Cool down when you choose

  • Warmup protects early steps, while Adam's $\hat v$ is still noisy
  • Decay lets the iterate settle instead of bouncing
  • WSD (MiniCPM, 2024): flat, then a short cooldown, branchable off any checkpoint
Same model, data, seed and batch order; only the schedule differs. During the stable phase WSD's loss sits above cosine (higher LR = more gradient noise), then drops sharply in the cooldown. The dashed branches start from checkpoints at 1600 and 2600 steps: the one at 3000 lands right on the cosine curve. You don't need to know your token budget in advance, which is why labs training many model sizes like it.
Gradient Hive · Day 2 · Engine Room20 / 38
🍯 Key takeaway

The learning rate is hyperparameter #1, and its schedule is #2.

Warm up, hold, cool down. Loss exploded? Halve the LR, check warmup, clip gradients at norm 1.0, and swap fp16 for bf16.

Full debugging checklist: LR too high, no warmup, no clipping, log(0) or division by zero, fp16 overflow, a bad batch (log per-batch loss), missing normalization, or residual branches initialized too large.

Grokking: delayed understanding

Sometimes the interesting learning starts after the model has memorized everything.

The art is computed from the network we're about to show. Each ring is the part of the learned number embedding that varies at one frequency k (the four the network chose: 30, 6, 41, 33), with tokens 0, 1, 2, … joined in order. A pure rotation by 2πk/97 per step draws a star polygon {97/k}. The network learned to represent numbers as angles.
Gradient Hive · Day 2 · Engine Room23 / 38
Power et al., 2022

Memorize first, understand later

  • Learn $(a+b) \bmod 97$ from 30% of the table
  • Train accuracy hits 100% by step ~40; test stays at chance
  • Keep going with weight decay: test jumps to 100%
  • The network found a Fourier algorithm: numbers as rotations, adding angles (Nanda et al., 2023)
Full-batch AdamW, lr 3e-3, weight decay 1.0. Memorized at step ~40, generalized at step ~2000: 49× later. Bottom: the grokked embedding puts ~90% of its power in four frequencies; the λ = 0 memorizer is spread flat. Weight decay slowly favors the compact general circuit over the bulky lookup table. In the lab you'll ablate λ and the data fraction and find these frequencies yourself.

06

Scaling laws: the physics of LLMs

Loss falls as a smooth power law in parameters, data and compute. So you can plan a budget.

Kaplan et al. (2020) showed the power laws; Hoffmann et al. (2022, "Chinchilla") showed many big models were under-trained. The art: isoFLOP curves from the Chinchilla law for 22 budgets from 10¹⁸ to 10²⁵ FLOPs, and the compute-optimal points joined by the white line.
Gradient Hive · Day 2 · Engine Room26 / 38
Chinchilla · 2022

Grow N and D together

$L = E + \dfrac{A}{N^{\alpha}} + \dfrac{B}{D^{\beta}}$

  • 100× compute → ~10× params, ~10× tokens
  • Optimum: ~20 tokens per parameter
  • Production over-trains: Llama 3 8B saw 15T tokens (~1,900 per param), because inference costs dominate
Both N* and D* grow roughly as √C, so 100× compute means ~10× each. Note on constants: the originally published fit (E 1.69, A 406.4, B 410.7, α 0.34, β 0.28) puts the optimum at more like 30–100 tokens/param; Epoch AI's 2024 replication found that fit inconsistent with Chinchilla's other two methods and refit it, which recovers ~20 tokens/param and Chinchilla-70B's 1.4T tokens. Beyond Chinchilla: the data wall (synthetic data, repeated epochs) and new scaling axes (RL post-training, test-time compute) on Day 5.
Gradient Hive · Day 2 · Engine Room27 / 38
🍯 Key takeaway

Loss is predictable: spend compute on parameters and tokens together.

~20 tokens per parameter minimizes training cost. If millions will query the model, train a smaller one for much longer.

Why do frameworks accumulate gradients with +=?

A value used in several places receives a gradient contribution from each use. The chain rule sums them.

Huge, noisy early updates while the weights and Adam's second-moment estimates are still far from equilibrium.

Six equations worth memorizing

Adjoint recursion

$$\bar v_i = \sum_{j\in\text{ch}(i)} \bar v_j\, \partial v_j/\partial v_i$$

He init

$$\mathrm{Var}(w) = 2/\text{fan}_{\text{in}}$$

RMSNorm

$$x / \sqrt{\overline{x^2}+\epsilon}\odot g$$

AdamW

$$\theta \leftarrow \theta - \eta\big(\hat m/(\sqrt{\hat v}+\epsilon) + \lambda\theta\big)$$

Muon

$$\Delta W \propto \mathrm{NS}(M) \approx UV^\top$$

Chinchilla

$$L(N,D) = E + A/N^{\alpha} + B/D^{\beta},\ C\approx 6ND$$

Day 2 · the honey jar · 1/2

🍯 What to remember

  1. Reverse-mode autodiff gives every gradient of a scalar loss for roughly the cost of a forward pass, at the price of storing activations.
  2. Trainability comes from variance-preserving init, (pre-)normalization, and residual streams that carry gradients straight through.
  3. AdamW (Adam + decoupled weight decay) is the default for transformers. L2 inside Adam is not the same thing.
  4. Muon orthogonalizes the momentum of 2-D weight matrices. It's a strong 2025-era alternative for hidden layers.

🍯 What to remember

  1. The learning rate is hyperparameter #1. Use warmup, then cosine or WSD decay, and clip gradients.
  2. Grokking: generalization can arrive long after memorization, and weight decay is what pushes the model there.
  3. Compute-optimal training scales N and D together (~20 tokens/param), but production models over-train small models because inference is what costs money.
